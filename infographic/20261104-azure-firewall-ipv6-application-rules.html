IPv6 アプリケーションルール対応
L7 フィルタリングが IPv6 トラフィックへ拡張

IPv6 の HTTP / HTTPS トラフィックに対するアプリケーションルール (レイヤー 7 フィルタリング) がパブリックプレビューに。デュアルスタック環境で IPv4 と一貫したアプリケーションレベル制御を実現。

📅 リリース日: 2026-11-04 | サービス: Azure Firewall | 機能: IPv6 アプリケーションルール (L7 フィルタリング)

📋概要

Azure Firewall の IPv6 サポートにおいて、アプリケーションルールがパブリックプレビューとして利用可能になりました。IPv6 の HTTP / HTTPS トラフィックに対するレイヤー 7 (アプリケーション層) フィルタリングが可能になり、IPv6 およびデュアルスタック環境にアプリケーションレベルの制御を拡張できます。

Azure Firewall の IPv6 サポート (デュアルスタックモード) は 2026 年 8 月にパブリックプレビューとして発表されましたが、その時点で IPv6 に対応していたのはネットワークルール (L3/L4) と DNS Proxy のみで、アプリケーションルールは未対応でした。今回のアップデートにより、Microsoft Learn ドキュメント上でもアプリケーションルールが IPv6 トラフィックを完全サポートする機能として記載され、IPv6 トラフィックの許可/拒否ルールをアプリケーション層で作成できるようになりました。これにより、IPv4 と IPv6 の間で一貫したポリシー運用を維持しやすくなります。

❌ Before (アップデート前の課題)

  • IPv6 サポート (デュアルスタックモード) ではネットワークルールと DNS Proxy のみが IPv6 対応。アプリケーションルール (FQDN ベースなどの L7 フィルタリング) は IPv6 トラフィックに適用できなかった
  • IPv4 ではアプリケーションルールで制御している通信を、IPv6 側ではネットワークルール (IP アドレス/ポートベース) でしか制御できず、IPv4/IPv6 間でポリシーの一貫性を保ちにくかった

✅ After (アップデート後の改善)

  • IPv6 の HTTP/HTTPS トラフィックに対してアプリケーションルールによるレイヤー 7 フィルタリングが可能に
  • アプリケーションルールで IPv6 トラフィックの許可/拒否ルールを作成でき、デュアルスタック環境でも IPv4 と一貫したアプリケーションレベルの制御を適用可能に

⚙️サービスアップデートの詳細

主要機能

🛡️

IPv6 トラフィックに対するアプリケーションルール

アプリケーションルールが IPv6 トラフィックを完全サポートし、IPv6 トラフィックの許可/拒否ルールを作成可能。IPv6 の HTTP および HTTPS トラフィックに対するレイヤー 7 フィルタリングを実現します。

🔄

IPv4/IPv6 間で一貫したポリシー運用

デュアルスタック環境において、IPv4 と IPv6 の両方にアプリケーションレベルの制御を適用でき、ポリシーの一貫性を維持しやすくなります。

🎯メリット

💼 ビジネス面

  • IPv6 移行 (デュアルスタック化) を進める組織が、IPv4 と同等のアプリケーションレベルのセキュリティ制御を IPv6 にも適用でき、移行時のセキュリティ要件を満たしやすくなる
  • IPv4/IPv6 で異なる制御方式を使い分ける必要がなくなり、ポリシー管理・監査の一貫性が向上する

🔧 技術面

  • IPv6 の HTTP/HTTPS トラフィックをレイヤー 7 でフィルタリングでき、IP アドレス/ポートベース (ネットワークルール) より粒度の高い制御が可能になる
  • 単一の Firewall Policy で IPv4/IPv6 両方のアプリケーションルールを一元管理できる

⚠️デメリット・制約事項

知っておくべき制約

  • パブリックプレビューであり、プレビューの補足利用条件が適用される。GA 日は未定
  • IPv6 では DNAT ルールが引き続き未サポート
  • IPv6 では Threat Intelligence、IDPS、Explicit Proxy、IP Groups ベースのシナリオが引き続き未サポート
  • Classic Azure Firewall および Virtual Hub (vHub) Firewall は未対応
  • 一度デュアルスタック化すると IPv4 のみのモードへ戻せない (GA 時に解消予定の一時的制限)

💡ユースケース

ユースケース 1: デュアルスタック環境での一貫したアウトバウンド Web フィルタリング

シナリオ

デュアルスタック VNet 上のワークロードからインターネットへのアウトバウンド HTTP/HTTPS 通信を、IPv4/IPv6 を問わずアプリケーションルールで制御したい。

実装ポイント
  • 既存の IPv4 ファイアウォールをデュアルスタックモードにアップグレードする
  • Firewall Policy のアプリケーションルールで IPv6 トラフィックの許可/拒否ルールを定義し、IPv4 と同等の L7 制御を適用する
効果

IPv6 側だけ制御が粗くなる (ネットワークルールのみ) 状態を解消し、IPv4/IPv6 で一貫したアウトバウンド制御を実現できる。

📝まとめ

2026 年 8 月の Azure Firewall IPv6 サポート (デュアルスタック) 発表時点ではネットワークルールと DNS Proxy に限定されていた IPv6 対応が、今回アプリケーションルール (L7 フィルタリング) に拡張されました。これにより、IPv6 の HTTP/HTTPS トラフィックにも FQDN ベースなどのアプリケーションレベル制御を適用でき、IPv4/IPv6 間で一貫したポリシー運用が可能になります。

一方で DNAT、Threat Intelligence、IDPS などは IPv6 で引き続き未対応のため、必要なセキュリティ機能が充足できるかを確認した上で、検証環境でのデュアルスタック構成とアプリケーションルールの評価を進めることを推奨します。
