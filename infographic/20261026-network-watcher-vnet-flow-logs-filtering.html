Azure Network Watcher Launched (GA) Networking

VNet フローログの
フィルタリング機能が一般提供 (GA)

IP アドレス・ポート・プロトコル・暗号化状態・フロー状態・トラフィック方向の条件で、記録するネットワークフローを絞り込み。ログ量とストレージコストを削減し、分析ノイズを低減。

📅 リリース日: 2026-10-26 ｜ 機能: VNet flow logs filtering

📰概要

Azure Network Watcher の仮想ネットワーク (VNet) フローログにおけるフィルタリング機能が一般提供 (GA) になりました。VNet フローログは、仮想ネットワークを流れる IP トラフィックの情報を記録し Azure Storage に送信する機能です。従来は記録対象を絞る手段がなく、VNet 内のすべてのフローが記録されていました。

🌐 IP アドレス 🔌 ポート 📡 プロトコル 🔐 暗号化状態 🔄 フロー状態 ↔️ トラフィック方向
ポイント: 監視・トラブルシューティング・セキュリティ・コンプライアンス・ネットワーク最適化において重要なトラフィックのみにログを絞り込めるようになり、ログ量の削減によるストレージコストの抑制と、分析時のノイズ低減が期待できます。従来の PowerShell に加えて Azure ポータルからも設定・管理が可能になりました。

❌ Before (アップデート前の課題)

  • VNet を通過するすべての IP フローが記録され、ログ量が大きくなりがちだった (ゲートウェイを通過するトラフィックなども既定で記録対象)
  • 不要なフローも含めてすべて記録されるため、ストレージコストが増加し、分析時に目的のフローを見つけにくかった

✅ After (アップデート後の改善)

  • IP / ポート / プロトコル / 暗号化状態 / フロー状態 / 方向の条件で記録するフローを絞り込み可能 ("Filtering helps reduce log volume by capturing only relevant flows")
  • 関連フローのみ記録でストレージコスト削減・ノイズ低減
  • Azure ポータルからもフィルタリングの設定・管理が可能に

VNet を流れるトラフィックフローのうち、フィルタ条件に一致したフローのみがログとして Azure Storage に保存され、Traffic Analytics や SIEM での分析に利用できます。条件に一致しないフローは記録されないため、ログ量を削減できます。

⚡主要機能

🎯

1. 条件ベースのフロー記録制御 (EnabledFilteringCriteria)

IP アドレス、ポート、プロトコル、暗号化状態、トラフィック方向などの条件式で、記録対象のフローを指定。VNet 内 (intra-VNet)・VNet 間 (inter-VNet)・CIDR 範囲ベース・インバウンド / アウトバウンド・インターネットトラフィック・許可 / 拒否トラフィックの識別に活用できます。

🔄

2. フロー状態 (RecordTypes) によるフィルタリング

フローのライフサイクル状態 (開始 B / 継続 C / 終了 E / 拒否 D) を指定して、必要なレコードタイプのみを収集。例: 拒否されたトラフィックのみ記録 ("D")、フローの作成・終了イベントのみ記録 ("B,E")。

♻️

3. 既存フローログのフィルタ条件更新

フローログを再作成することなく、Set-AzNetworkWatcherFlowLog でフィルタ条件を変更・削除できます。

🖱️

4. Azure ポータルでの設定・管理に対応

従来の PowerShell に加えて、Azure ポータルからフィルタリングを直接設定・管理できるようになりました。

🔧技術仕様

📋 フィルタ対象フィールド

フィールドフィルタ対象例
Directionトラフィックの方向Inbound, Outbound
SrcIP送信元 IP アドレス / CIDR 範囲192.168.1.1, 2001:db8::1/64
SrcPort送信元ポートの範囲・値1024-65535, 80, 443
DstIP宛先 IP アドレス / CIDR 範囲192.168.2.1, 2001:db8::2/64
DstPort宛先ポートの範囲・値22, 8080-8090
Protocolプロトコル種別TCP, UDP
Encryption暗号化状態サポートされる全暗号化状態の値、および NX_ALL (理由を問わず非暗号化)

✍️ フィルタ式の構文

項目詳細
比較演算子すべてのフィールドで = と != をサポート
論理演算子任意の 2 フィールド間で && (AND) と || (OR) をサポート
評価順序論理演算子の優先順位 (AND が OR より優先) に従い左から右に評価。括弧は現時点で未サポート
複数値の指定すべてのフィールドでカンマ区切りの値を指定可能。大文字小文字は区別しない
フィルタ文字列の最大長1,000 文字
RecordTypesB (開始) / C (継続、5 分間隔で統計) / E (終了、統計あり) / D (拒否) をカンマ区切りで指定

⚙️設定方法

✅ 前提条件

  • Network Watcher が有効なサブスクリプションと、対象の仮想ネットワーク
  • ログ保存先のストレージアカウント (仮想ネットワークと同一リージョン、Standard パフォーマンスレベル。Premium は未サポート)

💻 Azure PowerShell

PowerShell フィルタ条件付きで VNet フローログを作成 
# 仮想ネットワークとストレージアカウントの構成を変数に格納
$vnet = Get-AzVirtualNetwork -Name 'myVNet' -ResourceGroupName 'myResourceGroup'
$storageAccount = Get-AzStorageAccount -Name 'myStorageAccount' -ResourceGroupName 'myResourceGroup'

# フィルタ条件付き (dstip=20.252.145.59 || DstPort=54300-54400) で VNet フローログを作成
New-AzNetworkWatcherFlowLog -Enabled $true -Name 'myVNetFlowLog' `
    -NetworkWatcherName 'NetworkWatcher_eastus' -ResourceGroupName 'NetworkWatcherRG' `
    -StorageId $storageAccount.Id -TargetResourceId $vnet.Id `
    -FormatVersion 2 -EnabledFilteringCriteria 'dstip=20.252.145.59 || DstPort=54300-54400' `
    -EnableRetention $true -RetentionPolicyDays 15
PowerShell 既存フローログのフィルタ条件を更新 (再作成は不要) 
# 既存のフローログのフィルタ条件を更新 (再作成は不要)
Set-AzNetworkWatcherFlowLog -Enabled $true -Name 'myVNetFlowLog' `
    -NetworkWatcherName 'NetworkWatcher_eastus' -ResourceGroupName 'NetworkWatcherRG' `
    -StorageId $storageAccount.Id -TargetResourceId $vnet.Id `
    -FormatVersion 2 -EnabledFilteringCriteria 'dstip=20.252.145.59 || DstPort=443'
PowerShell フロー状態 (RecordTypes) によるフィルタリング 
# フロー状態 (RecordTypes) によるフィルタリング: 拒否されたトラフィックのみ記録
New-AzNetworkWatcherFlowLog -Enabled $true -Name 'myVNetFlowLog' `
    -NetworkWatcherName 'NetworkWatcher_eastus' -ResourceGroupName 'NetworkWatcherRG' `
    -StorageId $storageAccount.Id -TargetResourceId $vnet.Id `
    -RecordTypes "D"

🖱️ Azure Portal

本 GA により、Azure ポータルからもフィルタリングを直接設定・管理できるようになりました (公式アップデートに記載)。

💡メリット

💼 ビジネス面

  • 必要なフローのみを記録することで、フローログの収集量 (GB 単位課金) とストレージコストを削減
  • 監査・コンプライアンス対応で必要なトラフィック (例: 拒否されたトラフィック、非暗号化トラフィック) に絞った証跡を効率的に収集

🛠️ 技術面

  • 分析対象のログからノイズが減り、トラブルシューティングやセキュリティ分析の効率が向上
  • CIDR 範囲・ポート・方向などの条件で、調査対象のトラフィック (インターネットトラフィック、特定アプリケーションの通信など) を事前に絞り込み
  • フローログの再作成なしにフィルタ条件を変更できるため、運用中の調整が容易

⚠️デメリット・制約事項

  • フィルタ式で括弧 (ブラケット) は現時点で未サポート。評価は AND 優先・左から右の固定ルールに従う
  • フィルタ文字列の最大長は 1,000 文字
  • フィルタで除外したフローは記録されないため、条件設定を誤ると必要な証跡が欠落するリスクがある (フィルタ条件の設計には注意が必要)
  • VNet フローログ自体の制約が引き続き適用: ストレージアカウントは VNet と同一リージョン・Standard レベルが必要、Azure Container Instances / Azure Functions / App Service など一部サービスは未サポート
  • Microsoft Learn のフィルタリングドキュメント (2026-10-13 更新時点) にはプレビューの注記が残っているが、公式アップデート (2026-10-26) で GA が発表されている

🎯ユースケース

1

🛡️ 拒否されたトラフィックのみを記録してセキュリティ監視を効率化

シナリオ

NSG や Azure Virtual Network Manager のセキュリティ管理ルールで拒否されたトラフィックのみを記録し、不正アクセスの試行を効率的に監視する。

PowerShell 実装例 
New-AzNetworkWatcherFlowLog -Enabled $true -Name 'myDeniedFlowLog' `
    -NetworkWatcherName 'NetworkWatcher_eastus' -ResourceGroupName 'NetworkWatcherRG' `
    -StorageId $storageAccount.Id -TargetResourceId $vnet.Id `
    -RecordTypes "D"
効果

許可された正常トラフィックを記録対象から除外することで、ログ量を抑えつつ、セキュリティ分析に必要な拒否イベントに集中できる。

2

💰 特定の宛先・ポートへの通信のみを記録してログコストを削減

シナリオ

重要なワークロードへの通信 (特定の宛先 IP や HTTPS ポート) のみを記録し、フローログの収集量とストレージコストを削減する。

PowerShell 実装例 
New-AzNetworkWatcherFlowLog -Enabled $true -Name 'myFilteredFlowLog' `
    -NetworkWatcherName 'NetworkWatcher_eastus' -ResourceGroupName 'NetworkWatcherRG' `
    -StorageId $storageAccount.Id -TargetResourceId $vnet.Id `
    -FormatVersion 2 -EnabledFilteringCriteria 'dstip=20.252.145.59 || DstPort=443'
効果

監視対象外のフローを記録しないことで、GB 単位で課金されるフローログ収集量を削減できる。

💰料金

フィルタリング機能自体の追加料金に関する記載はなく、VNet フローログの既存の料金体系が適用されます。

項目料金
VNet フローログ収集収集されたログ 1 GB あたりの従量課金 (具体的な単価は料金ページでリージョン・通貨を指定して確認)
Traffic Analytics (有効化した場合)処理されたログ 1 GB あたりの従量課金 (高速処理: 10 分間隔 / 標準処理: 60 分間隔の 2 レベル。無料枠なし)
ログの保存Azure Blob Storage の料金が別途適用
🎁 無料枠: VNet フローログ収集はサブスクリプションあたり月 5 GB の無料枠あり。

フィルタリングにより収集されるログ量が減るため、フローログ収集・Traffic Analytics 処理・ストレージの各コスト削減につながります。詳細は Network Watcher 料金ページ を参照してください。

🌏利用可能リージョン

フィルタリング機能固有のリージョン情報は公式アップデートに記載されていません。VNet フローログ自体は主要なリージョン (Japan East / Japan West を含む) で利用可能です。最新のリージョン対応状況は VNet フローログ概要ドキュメントの Availability セクション を参照してください。

🧩関連サービス・機能

🗄️ Azure Storage

フローログの保存先。ログは 1 分間隔でブロック BLOB に取り込まれる。

📊 Traffic Analytics / Log Analytics

フローログを処理・可視化し、トラフィックの分析インサイトを提供する。

🕸️ Azure Virtual Network Manager

VNet フローログはセキュリティ管理ルールによる許可 / 拒否トラフィックの識別に対応。

🔐 仮想ネットワーク暗号化

フローの暗号化状態 (X / NX など) が記録され、フィルタ条件 (Encryption フィールド、NX_ALL など) としても利用可能。

📋 NSG フローログ

VNet フローログの前身にあたる機能。同一ワークロードで両方を有効化すると重複記録・追加コストが発生するため、NSG フローログの無効化が推奨される。

📝まとめ

✅ VNet フローログのフィルタリング機能が GA になり、IP アドレス・ポート・プロトコル・暗号化状態・フロー状態・トラフィック方向の条件で記録対象フローを絞り込めるようになりました。

💰 全フロー記録によるログ量・コスト増という従来の課題に対する直接的な解決策であり、PowerShell に加えて Azure ポータルからも設定できます。

🎯 VNet フローログを利用中、または NSG フローログからの移行を検討している環境では、拒否トラフィックのみの記録や重要ワークロードへの絞り込みなど、監視要件に応じたフィルタ設計によるコスト最適化の検討を推奨します。

⚠️ フィルタで除外したフローは記録されないため、監査要件を満たす条件設計には注意してください。
