マネージド Functions API の .NET 8 / .NET 9 サポート終了

📅 リリース日: 2026-11-09 🧩 機能: マネージド Functions API における .NET 8 / .NET 9 サポートの終了
サポート終了日 (移行期限)
2026 年 11 月 10 日
この日までにマネージド Functions API を .NET 10 (isolated worker) へ移行

📋 概要

Azure Static Web Apps のマネージド Functions API における .NET 8 および .NET 9 のサポートが 2026 年 11 月 10 日 に終了します。この日までに、マネージド Functions API を .NET 10 に移行する必要があります。

⚠️ サポート終了後の影響
アプリは動作を継続しますが、セキュリティ更新プログラムは提供されなくなり、Azure Functions 上での .NET 8 / .NET 9 のサポートも終了します。サポートされていないランタイムやバージョンでアプリを実行し続けると、セキュリティおよびパフォーマンス上の問題につながる可能性があります。
💡 既定ランタイムの変更
2026 年 11 月に、マネージド Functions API の既定の .NET ランタイムが .NET 10 に更新される予定です。staticwebapp.config.json で apiRuntime を明示的に設定することで、意図したランタイムでのビルド・実行が保証されます。

❌ Before (アップデート前・現状)

  • マネージド Functions API を .NET 8 (in-process / isolated) または .NET 9 (isolated) で実行可能
  • .NET 8 では in-process モデルも利用可能

✅ After (2026 年 11 月 10 日以降)

  • .NET 8 / .NET 9 へのセキュリティ更新の提供が終了 (アプリ自体は動作を継続)
  • サポートされる .NET ランタイムは .NET 10 (isolated worker モデルのみ) に
  • マネージド Functions API の既定の .NET ランタイムが .NET 10 に更新

2026 年 11 月 10 日以降は .NET 10 (isolated worker モデル) のみがサポート対象となるため、in-process モデルの .NET 8 アプリは isolated worker モデルへの移行も必要です。

🎯 サービスアップデートの詳細: 影響範囲

1️⃣

マネージド Functions API (.NET 8 in-process)

  • apiRuntime: dotnet:8.0 で稼働中の API が対象
  • .NET 10 は isolated worker モデルのみサポートのため、isolated worker モデルへの移行が必須
2️⃣

マネージド Functions API (.NET 8 / .NET 9 isolated)

  • apiRuntime: dotnet-isolated:8.0 / dotnet-isolated:9.0 で稼働中の API が対象
  • プロジェクトのターゲットを net10.0 に更新する必要がある
3️⃣

Bring your own functions (リンクされた Function Apps)

  • デプロイライフサイクルが別管理のため、個別にアップグレードとデプロイが必要

  • マネージド Functions のサポートは Azure Functions 言語ランタイムサポートポリシー に準拠

🔧 移行手順

in-process モデルを使用している場合

Migrate C# apps from the in-process model to the isolated worker model の .NET 10 向け手順に従い、API プロジェクト、パッケージ、スタートアップコード、関数コード、構成を isolated worker モデル用に更新します。

すでに isolated worker モデルを使用している場合

Update language versions in Azure Functions の C# 向け手順に従い、API プロジェクトのターゲットを net10.0 に更新します。

両方の構成に共通の手順

1

プロジェクトを .NET 10 ターゲットに更新

API プロジェクトが net10.0 をターゲットにしていることを確認し、Functions SDK とワーカーパッケージを .NET 10 isolated worker のプロジェクト・パッケージ要件 を満たすように更新する。ローカルでビルド・テストを実施する。

XML*.csproj
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
  </PropertyGroup>
</Project>
2

staticwebapp.config.json で API ランタイムを設定

JSONstaticwebapp.config.json
{
  "platform": {
    "apiRuntime": "dotnet-isolated:10.0"
  }
}

API プロジェクトの TargetFramework と staticwebapp.config.json の platform.apiRuntime の値は同じランタイムを指す必要があります。

3

静的 Web アプリを再デプロイ

静的 Web アプリを再デプロイし、Static Web Apps がマネージド API を .NET 10 でリビルド・公開するようにする。

⏰ 2026 年 11 月 10 日までに、必要なアップグレードをすべて完了し、API が in-process モデルから移行済みであることを確認してください。

⚠️ デメリット・制約事項

🔄

in-process モデルはコード変更を伴う移行が必要

.NET 10 は isolated worker モデルのみのサポートのため、in-process モデルのアプリはコード変更を伴う移行が必要

🛡️

期限超過時のセキュリティリスク

期限 (2026 年 11 月 10 日) までに移行しない場合、アプリは動作を継続するものの、セキュリティ更新が提供されず、セキュリティ・パフォーマンス上のリスクが生じる

🔗

Bring your own functions は個別対応が必要

Bring your own functions (リンクされた Function Apps) は別のデプロイライフサイクルを持つため、個別のアップグレードとデプロイが必要
