Azure Workload Center for SAP / Oracle と
Azure Copilot Run SAP / Oracle Agent

📅 リリース日: 2026-11-17 🧩 機能: Workload Center for SAP / Oracle + 専用 AI エージェント

📋概要

Microsoft Ignite に合わせて、Azure Workload Center for SAP と Azure Workload Center for Oracle が、専用 AI エージェント Azure Copilot Run SAP Agent / Run Oracle Agent とともに Limited Preview として発表。Workload Virtual Instance (WVI) を基盤とした「ワークロード認識型 (workload-aware)」の運用エクスペリエンスを提供する。
🧩
WVI は SAP システム (セントラルサービス、アプリケーションサーバー、DB サーバー、Web ディスパッチャーなど) や Oracle システムのコンポーネントと、それを支える Azure のコンピュート・ストレージ・ネットワークリソースを 1 つの論理的な Azure リソースとして表現
🔍
ワークロードの健全性把握、構成逸脱の特定、プラットフォーム障害がアプリケーションに与える影響の評価を、担当するシステムの文脈で実行可能に
📊
個々の Azure リソースを独立したインフラとして扱うのではなく、「ワークロード全体」としての構成管理・ヘルス監視・推奨事項・AI 支援トラブルシューティングを実現

❌ Before (アップデート前の課題)

  • SAP / Oracle システムを構成する VM・ストレージ・ネットワークなどの Azure リソースを個別に管理する必要があり、ワークロード全体の構成・健全性の把握には各インフラビューを手動でつなぎ合わせる必要があった
  • 障害発生時に、Azure プラットフォームの問題がどの SAP / Oracle コンポーネントに影響するかを、運用チームが手作業で調査・関連付けする必要があった
  • Azure / SAP on Azure / Oracle on Azure のベストプラクティスからの構成逸脱 (ドリフト) を継続的に検出する仕組みがなかった

✅ After (アップデート後の改善)

  • WVI によりシステム・コンポーネント・Azure リソースを単一ビューに統合し、ワークロード単位での管理が可能に
  • Azure Monitor のヘルスモデルにより、アプリ・DB・インフラの各レイヤーを横断した健全性インサイトと、劣化の発生箇所・影響範囲の特定が可能に
  • ベストプラクティスに対する構成検証が自動実行され、逸脱の内容・影響・修復手順を確認可能に
  • Run SAP / Run Oracle Agent に自然言語で質問し、構成変更の把握・影響評価・修復ガイダンスを取得 (変更の実行判断はチーム側に残る)

WVI が SAP / Oracle システムのコンポーネントと Azure リソースを 1 つのワークロードとして表現し、その文脈の上で構成検証・ヘルス監視・Advisor 推奨事項・Copilot エージェントによる AI 支援が提供される。

⚡主要機能

🧩

1. Workload Virtual Instance (WVI)

  • SAP / Oracle システムを表現する論理的な Azure リソース。アーキテクチャ、依存関係、メタデータ、運用コンテキストを単一ビューに集約
  • 既存リソースを移動・変更することなく、Azure リソースを「ワークロードコンポーネント」(例: Database Services、Application Services) にグループ化
  • SAP SID / Oracle SID や本番環境指定などのワークロード固有情報により、チームと AI エージェントが各環境を文脈的に理解
🔎

2. ワークロードの検出とオンボーディング

  • 既存の SAP / Oracle システムをオンボードすると WVI が作成される
  • Oracle は Oracle AI Database@Azure (Exadata Database Service on Dedicated Infrastructure、Oracle Autonomous AI Database など) と Azure VM 上の Oracle の両方に対応
✅

3. 構成検証とドリフト検出

  • Azure および SAP on Azure / Oracle on Azure のベストプラクティスに対して構成を継続的に評価
  • 逸脱の内容・影響・修復ガイダンスを提示
📊

4. ヘルス監視とトラブルシューティング

  • Azure Monitor のヘルスモデルで、システム・コンポーネント・リソースの健全性を階層的に可視化
  • 劣化の発生元と全体への影響範囲を特定
💡

5. ワークロードを考慮した推奨事項

  • WVI を構成するリソースに対する Azure Advisor の推奨事項をワークロードビュー内で表示し、影響コンポーネントに基づく優先順位付けが可能
🤖

6. Azure Copilot Run SAP / Run Oracle Agent (AI エージェント)

  • 自然言語で「何が変わったか」の把握、構成値の取得・比較、劣化の原因調査、影響評価、推奨される次のステップの特定を支援
  • Azure プラットフォーム障害とワークロードトポロジを相関させた影響分析 (インパクト分析) を提供
  • 意思決定と修復の実行権限はあくまで運用チーム側に残る設計

🌟メリット

💼 ビジネス面

  • ミッションクリティカルな SAP / Oracle ワークロードの障害調査時間を短縮し、ダウンタイムによるビジネス影響を低減
  • 構成逸脱を運用問題化する前にプロアクティブに是正でき、ベストプラクティス準拠を維持しやすい
  • SAP Basis / DBA チームとクラウド運用チームが同一のワークロードビューを共有でき、組織間の調査・連携コストを削減

🛠️ 技術面

  • インフラ単位ではなくワークロード単位の管理により、依存関係・影響範囲の手動の突き合わせ作業が不要に
  • Azure Monitor ヘルスモデルによるレイヤー横断 (アプリ / DB / インフラ) の健全性可視化
  • 自然言語での調査 (構成値の取得・比較、劣化原因の調査) により、トラブルシューティングの初動を高速化
  • AI エージェントは調査・ガイダンスに徹し、変更の実行はチームの判断に委ねられるため、ガバナンスを維持できる

💼ユースケース

🧾 ユースケース 1: SAP 本番システムの構成ドリフト検出と是正

シナリオAzure 上で複数の SAP 本番システム (SID 単位) を運用しており、SAP on Azure ベストプラクティスからの構成逸脱を定期的に棚卸ししたい。

実装例SAP システムを Workload Center にオンボードして WVI を作成し、構成検証の結果 (逸脱の内容・影響・修復手順) をワークロードビューで確認。Run SAP Agent に「前回から何が変わったか」を質問し、変更内容と影響を把握した上で是正する。

効果手動の構成棚卸し作業を削減し、逸脱が運用障害に発展する前に対処できる。

🚨 ユースケース 2: Azure プラットフォーム障害の Oracle ワークロードへの影響評価

シナリオAzure のインフラ障害発生時に、Oracle AI Database@Azure / Azure VM 上の Oracle システムのどのコンポーネントが影響を受けるかを迅速に判断したい。

実装例WVI のトポロジと Azure プラットフォームシグナルを相関させるインパクト分析を利用し、Run Oracle Agent に影響を受ける VM / コンポーネントを質問して初動対応を決定する。

効果障害時の影響範囲特定と根本原因調査を高速化し、MTTR を短縮できる。
