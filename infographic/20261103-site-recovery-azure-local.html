Launched (GA) Azure Site Recovery Azure Local

Azure Site Recovery
Azure Local 向けサポートが一般提供開始 (GA)

Azure Local 上の Windows / Linux VM を Azure へレプリケーション。オンプレミスの災害対策 (DR) をクラウドに拡張

📅 リリース日: 2026-11-02 (GA 時期: 2026 年 10 月) 🧩 機能: Azure Site Recovery for Azure Local

📌概要

Azure Site Recovery (ASR) による Azure Local のサポートが一般提供 (GA) となりました。Azure Local 上で稼働するサポート対象の Windows / Linux 仮想マシンを Azure にレプリケーションすることで、オンプレミス環境の災害対策 (DR) をクラウドに拡張できます。エンタープライズグレードの DR が、これまで以上にシンプルかつセキュアに、容易にセットアップできるようになりました。

ポイント: Azure portal 上の Azure Local リソースから合理化されたセットアップを開始でき、本番のレプリケーションを中断することなくテストフェールオーバーで復旧計画を検証可能。計画的・非計画的な停止時には Azure へフェールオーバーし、オンプレミス復旧後は Azure Local へフェールバックできます。Azure Local がサポートされるすべてのリージョンで利用可能です。

❌ Before (アップデート前の課題)

  • Hyper-V 向け ASR の有効化は、Azure portal の複数ブレードにまたがる多段階設定が必要で、ノードごとに繰り返し作業が発生
  • WDAC (App Control) 強制モード環境では、エージェント導入のために一時的に監査モードへ切り替える回避策が必要
  • プロキシ設定はメインのセットアップフロー外での手動手順が必要

✅ After (アップデート後の改善)

  • 単一ページのウィザードで DR 環境全体を準備 (コンテナー・Hyper-V サイト作成、全ノードへのエージェント自動インストール、ポリシー関連付け、ホスト登録を一括実行)
  • WDAC 強制モードを維持したまま ASR エージェントをインストール可能
  • プロキシのホスト・ポート・資格情報をウィザード内で直接設定し、クラスター全体に一貫適用 (個別構成ファイルや手動手順が不要)

Azure Local 上の VM の仮想ハードディスクを Azure のストレージへ継続的にレプリケートし、災害時には Azure VM としてフェールオーバー、オンプレミス復旧後はフェールバックと逆レプリケーションで保護を再開します。

⚙️サービスアップデートの詳細: 主要機能

🧙

1. 一元化されたデプロイウィザード

  • Azure portal の Azure Local リソースの「Capabilities」タブにある「Disaster recovery」タイルから、1 ページのウィザードで DR インフラ全体を準備
  • Recovery Services コンテナーと Hyper-V サイトの作成、全ノードへの ASR エージェントの自動ダウンロード・インストール、レプリケーションポリシーの関連付け、ホスト登録までを一括実行
  • マネージド ID がコンテナー登録キーを取得し、エージェントのインストールを完了
🛡️

2. WDAC 強制モード対応

Application Control ポリシーを無効化・緩和することなくエージェントをインストール可能

🌐

3. 組み込みプロキシ対応

プロキシのホスト・ポート・資格情報をウィザード内で設定し、クラスター全体に一貫適用

🔁

🛠️設定方法

✅ 前提条件

  1. 保護対象 VM をホストする Azure Local がインターネットにアクセスできること (レプリケーションのため)
  2. Azure Local が登録済みであること
  3. マネージド ID へ権限を割り当てるための Recovery Services コンテナーに対する所有者権限、および Azure Local リソースとその子リソースに対する読み取り/書き込み権限
  4. キャパシティプランニングツールでレプリケーションとフェールオーバーの要件を事前評価すること

🖱️ Azure Portal での手順

  1. インフラの準備: Azure Local システムの「Overview」→「Capabilities」タブ →「Disaster recovery」タイル →「Protect VM workloads」→「Prepare infrastructure」を選択。Recovery Services コンテナー、Hyper-V サイト、レプリケーションポリシーを新規作成または既存から選択して実行
  2. レプリケーションの有効化: Recovery Services コンテナーで「Replicate」→「Hyper-V machines to Azure」を選択し、ソース環境 (Hyper-V サイト)、ターゲット環境 (サブスクリプション、フェールオーバー後のリソースグループ、ストレージ、仮想ネットワーク)、対象 VM、OS 種別とディスク、レプリケーションポリシーを指定
  3. テストフェールオーバー: VM が「Protected」状態になったら、分離ネットワークでテストフェールオーバーを実行して DR 計画を検証
  4. 復旧計画の作成: Recovery Services コンテナーで VM をグループ化し、起動順序と自動化を定義
  5. フェールオーバー / フェールバック / 逆レプリケーション: 災害時は Azure へフェールオーバーし、復旧後はフェールバックと逆レプリケーションで保護を再開

🌟メリット

💼 ビジネス面

  • オンプレミス (Azure Local) 環境にエンタープライズグレードの DR をクラウドベースで追加でき、セカンダリデータセンターの構築・維持が不要
  • 本番レプリケーションを中断しないテストフェールオーバーにより、DR 訓練を安全に実施可能
  • フェールオーバー/テストフェールオーバー実行時のみコンピューティング料金が発生するため、平常時の DR サイト維持コストを抑制

🧑‍💻 技術面

  • 単一ウィザードによるセットアップで、ノードごとの繰り返し作業や複数ブレードにまたがる設定が不要
  • WDAC 強制モードやプロキシ環境といったセキュリティ要件の厳しい環境でもセキュリティ構成を緩めずに導入可能
  • 復旧計画により、複数 VM で構成されるアプリケーションの起動順序制御と復旧タスクの自動化が可能

⚠️デメリット・制約事項

  • Arc 拡張機能: Arc によってインストールされた拡張機能は、フェールオーバー後の Azure VM 上では表示されず、Azure 側での管理 (インストール・アップグレード・アンインストール) ができない
  • ゲスト構成ポリシー: VM が Azure 上にある間、ゲスト構成ポリシー (OS のセキュリティ・構成の監査) は実行されない (オンプレミスへ戻るまで)
  • ログデータ: ログデータ (Sentinel、Defender、Azure Monitor) は、Azure 上では Azure VM に、オンプレミスでは Arc 対応サーバーに関連付けられる。portal の UX はリソース ID でデータを検索するため、各リソースでは一部のログしか表示されない (コンピューター名での検索で全ログを確認可能)
  • Azure VM ゲストエージェント: オンプレミスへ戻す可能性がある場合、Arc との競合を避けるためインストールは非推奨 (インストールする場合は拡張機能管理を無効化する)
  • 手動介入: フェールオーバー後に Azure Local 側の VM を削除した場合、Azure Local での管理を継続するには手動の介入が必要
  • 既知の問題: Hyper-V が未セットアップのホストや、別の Hyper-V サイトに既に関連付けられたホストでは ASR エージェントのインストールが失敗する

💡ユースケース

ユースケース 1: Azure Local 上の基幹系 VM のクラウド DR

シナリオ単一拠点の Azure Local 上で稼働する基幹系の Windows / Linux VM について、拠点全体の障害 (災害・停電など) に備えたい。セカンダリ拠点を持たないため、Azure を DR サイトとして利用する。

実装例Azure portal で Azure Local リソースの「Disaster recovery」タイルからインフラを準備し、対象 VM のレプリケーションを有効化。復旧計画でアプリケーションの起動順序を定義し、四半期ごとにテストフェールオーバーで DR 訓練を実施する。

効果セカンダリデータセンターなしで拠点障害に備えられ、障害時は Azure 上でワークロードを継続。復旧後はフェールバックと逆レプリケーション (差分のみ) で迅速に元の環境へ復帰できる。

ユースケース 2: WDAC 強制モード環境への DR 導入

シナリオセキュリティ要件により WDAC (App Control) を強制モードで運用している Azure Local 環境に、セキュリティポリシーを緩めることなく DR を導入したい。

実装例GA 版のデプロイウィザードを使用し、WDAC 強制モードを維持したまま全ノードに ASR エージェントをインストール。プロキシ経由の通信もウィザード内で設定する。

効果従来必要だった監査モードへの一時切り替えが不要になり、セキュリティ態勢を維持したまま DR を構成できる。

💰料金

Azure Site Recovery は保護対象インスタンス単位の月額課金です。

31 日間無料

保護対象インスタンスは最初の 31 日間無料。32 日目以降 (Azure への復旧) は保護対象インスタンスあたり月額課金 (最新の金額は料金ページを参照)

項目料金
保護対象インスタンス (最初の 31 日間)無料
保護対象インスタンス (32 日目以降、Azure への復旧)保護対象インスタンスあたり月額課金 (最新の金額は料金ページを参照)
  • 課金は月間の「平均日次保護インスタンス数」単位
  • 無料期間中もレプリカストレージ、ストレージトランザクション、スナップショット (復旧ポイント、マネージドディスク料金) は課金対象
  • フェールオーバー / テストフェールオーバー実行時のみ Azure VM のコンピューティング料金が発生

🔗関連サービス・機能

🏢 Azure Local

保護対象の Hyper-V VM が稼働するハイブリッドインフラ。Azure portal 上の Azure Local リソースから DR のセットアップを開始する

🌐 Azure Arc

Azure Local の VM は Arc 対応で管理される。フェールオーバー中は Arc 拡張機能の管理やゲスト構成ポリシーに制約がある点に注意

🔐 Recovery Services コンテナー (Azure Backup / Site Recovery)

レプリケーションポリシーや保護対象 VM の構成情報を格納し、フェールオーバー以降の操作を実施する

💾 Azure Storage / マネージドディスク

レプリケーション先のストレージ。マネージドディスクの利用が推奨される

📊 Azure Monitor / Microsoft Sentinel / Microsoft Defender

ログデータはフェールオーバー中とオンプレミス稼働中で関連付け先リソースが変わる

📝まとめ

Azure Site Recovery の Azure Local サポートが GA となり、Azure Local 上の Windows / Linux VM を Azure へレプリケートするエンタープライズグレードの DR が正式に利用可能になりました。GA 版では単一ページのデプロイウィザード、WDAC 強制モード対応、組み込みプロキシ対応により、Preview 時に課題だったセットアップの煩雑さとセキュリティ要件との両立が大きく改善されています。

Azure Local を運用し、セカンダリ拠点を持たずに DR を実現したい組織にとって有力な選択肢です。まずは最初の 31 日間の無料期間を活用して対象 VM のレプリケーションとテストフェールオーバーを検証し、復旧計画の整備と定期的な DR 訓練への組み込みを推奨します。

なお、フェールオーバー中は Arc 拡張機能の管理やゲスト構成ポリシーに制約がある点、Trusted Launch VM 対応や代替オンプレミス拠点へのフェールバックは将来リリース予定である点に留意してください。
