🐧 Azure Linux Launched (GA) Microsoft Ignite 発表

Azure Linux 4.0 が一般提供開始 (GA)
Azure VM / VM Scale Sets の汎用サーバー OS に

Microsoft ファーストパーティのオープンソース Linux ディストリビューション (Fedora 派生・RPM ベース)。Azure のコンピューティング・ストレージ・ネットワークに最適化。

📅 リリース日: 2026-11-17

📌概要

Microsoft Ignite にて、Azure Linux 4.0 が Azure Virtual Machines および VM Scale Sets 向けに一般提供 (GA) となりました。Azure Linux は Microsoft が開発・保守するファーストパーティの Linux ディストリビューションで、すでに Azure 内部では AI ワークロード、AKS、App Service、Cosmos DB などで数百万コア規模の稼働実績があります。

4.0 のポイント: Linux カーネル 6.18 LTS、新パッケージマネージャー dnf5、glibc 2.42、OpenSSL 3.5、Python 3.14 などモダン化されたスタックを搭載。最小パッケージ構成により VM の起動・プロビジョニングを高速化し、攻撃対象領域を削減。OS ライセンス費用は不要 (Azure コンピューティング料金に含まれる)。

❌ Before (アップデート前の課題)

  • Azure Linux 4.0 はプレビュー段階では評価・テスト用途に限定され、本番環境では利用不可
  • 汎用 VM にサードパーティ製ディストリビューションを使う場合、OS ライセンス料・別途サポート契約・ベンダー間調整が必要なケースも
  • 旧バージョンの tdnf パッケージマネージャーは依存関係解決の性能に課題

✅ After (アップデート後の改善)

  • Azure VM / VM Scale Sets で本番利用が可能に (顧客 VM 向け汎用サーバー OS として設計された初のリリース)
  • OS とクラウド基盤を Microsoft が単一ベンダーとして提供し、カーネルから CVE 対応までサプライチェーンを一貫管理 (Critical/High CVE の迅速なパッチ + 月次セキュリティ更新)
  • dnf5 により依存関係解決の高速化とメモリ使用量の削減
  • 追加の OS ライセンス費用やサポート契約が不要

Azure Marketplace から Azure Linux 4.0 イメージを取得し、VM / VM Scale Sets にデプロイできます。同一のサプライチェーンでビルドされたコンテナーイメージが MCR で提供され、WSL 上でも同じ OS を使った開発・テストが可能です。

⚡主要機能 (サービスアップデートの詳細)

⚙️

1. Azure チューニング済みカーネル (Linux 6.18 LTS)

Hyper-V 統合の改善、GPU/AI アクセラレータ対応、新ハードウェアドライバーを搭載。

🔒

2. セキュアバイデフォルト

Secure Boot、Trusted Launch、SELinux (既定で有効)、カーネル強化、署名済みドライバー、ポスト量子暗号対応。SBOM を SLSA Level 3 を目標として公開。

🪶

3. 最小フットプリント

クラウドワークロードに必要なパッケージのみを同梱し、初日から攻撃対象領域を削減。起動・プロビジョニングも高速化。

💰

4. 追加 OS ライセンス費用なし

Azure コンピューティング料金に含まれ、別途の OS ライセンス料やサポート契約が不要。

🛡️

5. Microsoft 管理のサプライチェーン

カーネルから CVE 対応まで一貫管理。Critical/High CVE への迅速なパッチ提供と月次セキュリティ更新。

📅

6. 予測可能なライフサイクル

LTS カーネルによるフルサポートと、新ハードウェア向けの年次 HWE カーネル更新。

📦

7. コンテナーイメージの提供

VM と同じサプライチェーンでビルドされた Base (Core) / Runtime (Python, Node.js, Java, .NET) / Distroless イメージを Microsoft Container Registry (MCR) で提供。

💻

8. WSL 対応

WSL 上で Azure Linux を利用でき、デプロイ先と同じ OS で VS Code や CLI を使った開発・テストが可能。

🛠️設定方法

前提条件

  • Azure サブスクリプション
  • Azure CLI (イメージの検索・VM 作成に使用)

Azure CLI

Azure Linux 4.0 イメージは Azure Marketplace のパブリッシャー microsoftazurelinux から提供されています (x86_64 Gen2: microsoftazurelinux:azurelinux-4:4:latest、ARM64 Gen2: microsoftazurelinux:azurelinux-4:4-arm64:latest)。

bashAzure CLI
# パブリッシャーのオファー一覧を表示
az vm image list-offers --publisher microsoftazurelinux --location eastus

# オファーの SKU 一覧を表示
az vm image list-skus --publisher microsoftazurelinux --offer azurelinux-4 --location eastus

# SKU の全バージョンを表示
az vm image list --publisher microsoftazurelinux --offer azurelinux-4 --sku 4 --all

# 特定イメージバージョンの詳細を表示
az vm image show --urn microsoftazurelinux:azurelinux-4:4:latest

Azure Portal

Azure Portal の Marketplace から microsoftazurelinux.azurelinux-4 を検索して VM を作成できます。手順の詳細は Microsoft Learn のクイックスタートを参照してください。

👍メリット

💼 ビジネス面

  • 追加の OS ライセンス費用・サポート契約が不要で、Linux VM の TCO を削減
  • OS とクラウド基盤が単一ベンダー (Microsoft) に統一され、障害時の切り分けやサポート窓口が一本化
  • Azure 内部 (AKS、App Service、Cosmos DB など) での数百万コア規模の稼働実績

⚙️ 技術面

  • Azure VM SKU で検証済みで、Defender for Cloud、Azure Monitor、Trusted Launch のサポートを内蔵
  • 最小パッケージ構成により起動・プロビジョニングが高速で、攻撃対象領域が小さい
  • SELinux 既定有効、Secure Boot、ポスト量子暗号対応などセキュリティ第一の設計
  • LTS カーネル + 年次 HWE カーネル更新による予測可能なライフサイクル
  • VM・コンテナー (MCR)・WSL で同一サプライチェーンの OS を利用でき、開発から本番まで環境を統一

⚠️ デメリット・制約事項

  • デスクトップ / GUI 用途は対象外 (サーバー OS として設計)
  • 旧バージョンで使われていた tdnf から dnf5 に変更されたため、tdnf を参照するスクリプト、Dockerfile、CI パイプラインは dnf5 または dnf への更新が必要
  • FIPS 140-3 認証は取得手続き中のため、FIPS が必須のワークロードは認証済みリリースを使用する必要あり
  • 既定の OS ディスクサイズは 5 GB と小さく、必要に応じて拡張が必要
  • 最小構成のため、必要なパッケージは packages.microsoft.com から追加インストールする運用が前提

1Azure 最適化された汎用サーバー OS への移行

シナリオ: サードパーティ製 Linux ディストリビューションで稼働している Web / アプリケーションサーバーを、ライセンスコスト削減とセキュリティ運用の簡素化のために Azure Linux 4.0 に移行する。

実装例:

bashAzure CLI
# Azure Linux 4.0 イメージの確認

✅ 効果: OS ライセンス費用の削減、Microsoft 一元管理による CVE 対応の迅速化、最小フットプリントによるセキュリティリスクの低減。
2VM Scale Sets によるスケールアウト構成

シナリオ: 需要に応じて自動スケールする Web フロントエンドを、起動が高速な Azure Linux 4.0 ベースの VM Scale Sets で構成する。

✅ 効果: 最小パッケージ構成による高速なプロビジョニングで、スケールアウト時の応答性が向上。Image Customizer と Azure Compute Gallery を組み合わせてカスタムイメージを一貫してデプロイ可能。
3開発から本番までの OS 統一

シナリオ: WSL 上の Azure Linux で開発・テストを行い、MCR の Azure Linux コンテナーイメージ (Runtime / Distroless) と Azure VM 上の Azure Linux 4.0 で本番運用することで、環境差異を排除する。

✅ 効果: 開発環境と本番環境の OS・サプライチェーンが統一され、環境差異による不具合を削減。Distroless イメージによりコンテナーの攻撃対象領域も最小化。

📝まとめ

Azure Linux 4.0 の GA により、Microsoft ファーストパーティの Linux ディストリビューションを顧客の汎用 VM ワークロードで本番利用できるようになりました。OS ライセンス費用が不要で、カーネルから CVE 対応までを Microsoft が一貫管理する点は、Linux VM の TCO 削減とセキュリティ運用の簡素化の両面で大きな価値があります。

Solutions Architect としては、新規 Linux VM ワークロードの OS 選定肢として Azure Linux 4.0 を評価に加えるとともに、既存の Azure Linux 利用環境では tdnf から dnf5 への移行影響 (スクリプト、Dockerfile、CI パイプライン) を確認することを推奨します。FIPS 140-3 が必須のワークロードは認証取得完了まで認証済みリリースを使用してください。
