コントロールプレーンを Microsoft 管理側へオフロード。ワーカー 2 ノード・約 15〜20 分でクラスターを構築できる新デプロイオプションが Microsoft Ignite に合わせて GA

📅 リリース日: 2026-11-17

📋概要

Microsoft は、Azure Red Hat OpenShift (ARO) の新しいデプロイオプション Hosted Control Planes (HCP) の一般提供 (GA) を Microsoft Ignite に合わせて発表しました。HCP アーキテクチャでは、OpenShift のコントロールプレーン (API サーバーや etcd など) をアプリケーションが稼働するワーカーノードから分離し、Microsoft 管理の Azure サブスクリプション内でフルマネージドサービスとして稼働させます。利用者は自身のサブスクリプションと仮想ネットワークにワーカーノードのみをデプロイします。

HCP はアプリケーションのモダナイゼーション加速、開発者の生産性向上、運用の効率化、セキュリティ強化を支援しつつ、Microsoft と Red Hat が共同でエンジニアリング・サポートを提供する従来どおりの OpenShift エクスペリエンスを維持。HCP は Red Hat OpenShift 5 をサポートし、Azure 上で最新の OpenShift 機能を統合サポート体験とともに利用できます。従来の標準アーキテクチャ版 ARO も引き続きフルサポートされます。

❌ Before (標準アーキテクチャ)

  • コントロールプレーン 3 台 + ワーカー 3 台の最小構成が必要で、コントロールプレーン分の VM コストも利用者負担
  • クラスター作成に約 45 分かかる
  • コントロールプレーンとワーカーのアップグレードが一体で、個別に制御できない
  • Ingress コントローラーやイメージレジストリなどのプラットフォームコンポーネント用に専用インフラストラクチャノードが必要

✅ After (Hosted Control Planes)

  • コントロールプレーンは Microsoft 管理サブスクリプションでホスト。利用者はワーカーノード (最小 2 台) 分のみ支払い
  • プロビジョニングが約 15〜20 分に短縮
  • コントロールプレーンと各ノードプールを個別にアップグレード可能。z-stream (パッチ) は Red Hat SRE が自動管理
  • 専用インフラノード不要。プラットフォームコンポーネントはワーカーノード上で稼働

🛠️設定方法

前提条件

  1. Azure CLI バージョン 2.93.0 以上
  2. クラスターの作成・実行に最低 20 コアのリソースクォータが必要 (新規サブスクリプションの既定クォータでは不足する場合あり)
  3. 対象リソースグループまたはサブスクリプションに対する Contributor + User Access Administrator 権限、または Owner 権限
  4. リソースプロバイダーの登録: Microsoft.RedHatOpenShift、Microsoft.Compute、Microsoft.Storage、Microsoft.Authorization

Azure CLI

bashHCP クラスターの作成
# リソースプロバイダーの登録
az provider register --namespace Microsoft.RedHatOpenShift --wait
az provider register --namespace Microsoft.Compute --wait
az provider register --namespace Microsoft.Storage --wait
az provider register --namespace Microsoft.Authorization --wait

# VNet 統合サブネットの作成 (HCP 専用の委任が必要)
az network vnet subnet create \
  --name "${CUSTOMER_VNET_INTEGRATION_SUBNET_NAME}" \
  --vnet-name "${CUSTOMER_VNET_NAME}" \
  --resource-group "${CUSTOMER_RG_NAME}" \
  --address-prefixes 10.0.1.0/24 \
  --delegations Microsoft.RedHatOpenShift/hcpOpenShiftClusters

# HCP クラスターの作成 (抜粋。マネージド ID や KMS キーの指定が別途必要)
az aro hcp cluster create \
  --name "${CLUSTER_NAME}" \
  --resource-group "${CUSTOMER_RG_NAME}" \
  --location "${LOCATION}" \
  --version "${CLUSTER_VERSION}" \
  --subnet-id "${SUBNET_ID}" \
  --vnet-integration-subnet-id "${VNET_INTEGRATION_SUBNET_ID}" \
  --nsg "${NSG_ID}" \
  --kms-vault-name "${KEYVAULT_NAME}" \
  --kms-active-key "{name:${KMS_KEY_NAME},version:${KMS_KEY_VERSION}}"

# ノードプールの作成 (ワーカーノード 2 台)
az aro hcp cluster nodepool create \
  --cluster-name "${CLUSTER_NAME}" \
  --name "${NP_NAME}" \
  --resource-group "${CUSTOMER_RG_NAME}" \
  --replicas 2 \
  --vm-size Standard_D8s_v6 \
  --version "${NP_VERSION}"

クラスター作成にはコントロールプレーンオペレーター用・データプレーンオペレーター用の複数のマネージド ID の作成とロール割り当て、Key Vault での KMS キー作成が必要です。完全な手順は クイックスタート を参照してください。

Azure Portal

Azure Portal から直接 HCP クラスターを作成・構成できます。Bicep / ARM テンプレートによるデプロイにも対応しています。

💎メリット

💼 ビジネス面

  • コントロールプレーン 3 ノードと専用インフラノードの VM コストが不要になり、最小ワーカー 2 ノードから開始できるためクラスターあたりの TCO を削減
  • クラスター作成が約 15〜20 分に短縮され、環境構築や検証のリードタイムが短縮
  • Microsoft と Red Hat の共同エンジニアリング・共同サポート体制が HCP でも維持

⚙️ 技術面

  • コントロールプレーンの運用 (API サーバー、etcd、パッチ適用) を Red Hat SRE にオフロード
  • コントロールプレーンとノードプールを個別にアップグレードでき、メンテナンスの柔軟性が向上
  • CMK による OS ディスク暗号化、独自 ID プロバイダー構成など、ガバナンス要件に対応
  • Azure CLI / ARM / Bicep による IaC ワークフローに統合可能

🚧デメリット・制約事項

  • クラスターの作成・実行に最低 20 vCPU コアのクォータが必要
  • ワーカーサブネットに加えて、Microsoft.RedHatOpenShift/hcpOpenShiftClusters に委任された専用の VNet 統合サブネットが必要
  • プラットフォームコンポーネント (Ingress、レジストリ、監視) がワーカーノード上で稼働するため、ワーカーノードのサイジングでその分を考慮する必要がある
  • GA 時点の提供リージョンは 8 リージョンに限定 (追加リージョンは GA 後に展開予定)
  • コントロールプレーンは顧客のサブスクリプション外でホストされるため、コントロールプレーンノードを直接参照・操作する運用はできない

📝まとめ

Azure Red Hat OpenShift with hosted control planes の GA により、OpenShift のコントロールプレーン運用を Microsoft / Red Hat 側にオフロードし、ワーカーノード 2 台からの小さな構成を約 15〜20 分でプロビジョニングできるようになりました。コントロールプレーン分の VM コストが不要になるため、特に複数クラスターや開発・検証環境を運用する組織にとってコスト面・運用面のインパクトが大きいアップデートです。

OpenShift を Azure で利用中・検討中の場合は、標準アーキテクチャとの比較ドキュメントを確認のうえ、新規クラスターでの HCP 採用を検討することを推奨します。提供リージョンが現時点で 8 リージョンに限られる点と、専用の VNet 統合サブネット委任やマネージド ID のセットアップが必要になる点は事前に確認してください。
